# Общие черновики

Черновик принадлежит внутреннему `User.id`, поэтому один человек видит его
из бота и мини-приложения после входа под тем же аккаунтом MAX. Таблица
`system.drafts` уже включена в начальную миграцию. Физического удаления нет;
срок хранения и очистка пока не определены.

Поддерживаются `flow_kind=issue_card` и `flow_kind=resident_request`. `payload`
содержит только поля соответствующих `/issues/create_card` и
`/access/create_resident_request`. Он может быть неполным: сохранение черновика
не равно проверке готовности обращения. Размер JSON — не более 32 КиБ.

- `GET /drafts/list?flow_kind=...` — последние 50 своих записей, включая
  отправленные; фильтр необязателен.
- `GET /drafts/get?draft_id=...` — свой черновик, иначе 404 без раскрытия
  существования чужого.
- `POST /drafts/save` — создание без `draft_id`/`revision` или обновление с обоими.
  При обновлении нужно передать текущую версию; новая версия увеличивается на 1.
- `POST /drafts/submit` — только отметка `submitted_at` с текущей версией,
  без создания предметной заявки. Повтор и устаревшая версия дают 409.

Для обычного пути мини-приложение сначала вызывает предметную ручку создания,
затем помечает черновик отправленным. Если после сетевого сбоя судьба создания
неизвестна, клиент должен перечитать предметный список, прежде чем создавать
обращение заново. Для изменяющих запросов можно передать `Idempotency-Key`;
повтор того же ключа возвращает 409, а не сохранённый успешный ответ.

В боте `/draft send UUID revision` валидирует полный `payload`, атомарно
помечает черновик и вызывает существующую предметную функцию. `/draft submit`
ставит только отметку после самостоятельной подачи. Все команды доступны через
`/drafthelp`; адаптер бота подключает `handle_draft_text` отдельно.
