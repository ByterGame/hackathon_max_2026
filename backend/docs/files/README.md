# Закрытые вложения

Файлы хранятся в постоянном томе `FILE_STORAGE_ROOT`; значение переменной
обязательно, путь должен быть абсолютным. В таблице `system.files` лежат только
метаданные и случайный ключ файла. Директория не монтируется в nginx или
`StaticFiles`, а ключ не возвращается клиенту. Все запросы требуют подписанный
заголовок `X-Max-Init-Data`.

## Контракт HTTP

`POST /files/upload?filename=<имя>&draft_id=<UUID>` — загрузить файл в свой
черновик `issue_card`. Вместо `draft_id` можно передать одновременно
`parent_kind` и `parent_id`, чтобы сразу привязать файл к уже созданному
родителю. Допустимые `parent_kind`: `issue_report`, `issue_message`,
`company_registration`, `house_addition`. Тело — сами байты, **не** JSON и не
multipart. `Content-Type` должен соответствовать содержимому. Пример браузера:

```ts
const params = new URLSearchParams({
  filename: file.name,
  parent_kind: 'issue_report',
  parent_id: reportId,
});
await fetch(`/files/upload?${params}`, {
  method: 'POST',
  headers: { 'Content-Type': file.type, 'X-Max-Init-Data': initData },
  body: file,
});
```

Допустимы JPEG (`.jpg`, `.jpeg`), PNG, WebP, PDF, MP4 и MOV; размер — от
1 байта до 8 МиБ включительно. Проверяются объявленный MIME, расширение
имени и сигнатура содержимого. Из имени удаляются компоненты пути и
управляющие символы. Неподдерживаемый или подменённый файл отклоняется;
проверка не заменяет антивирус для будущего документооборота.

`POST /files/attach` с JSON
`{"file_id":"UUID","parent_kind":"issue_report","parent_id":"UUID"}`
привязывает staged-файл своего черновика к своему исходному описанию карточки
того же дома. Повторное прикрепление даёт 409.

`GET /files/list?parent_kind=issue_report&parent_id=<UUID>` возвращает
`{"files":[...]}`. Для staged-файлов можно вызвать
`GET /files/list?parent_kind=draft&parent_id=<UUID>`; их видит только владелец
черновика. Объект файла содержит `id`, `draft_id`, `parent_kind`, `parent_id`,
`original_name`, `mime_type`, `size_bytes`, `sha256`, `state`, `created_at`,
`ready_at`; пути и ключа хранилища в ответе нет.

`GET /files/download?file_id=<UUID>` возвращает байты с
`Content-Disposition: attachment`, `Cache-Control: private, no-store` и
`X-Content-Type-Options: nosniff`. Ссылка сама по себе не даёт доступа:
проверяются текущие права на исходную заявку/сообщение. Для жителя это
действующий доступ к дому и текущая область карточки, для сотрудника —
действующее назначение в УК, для обращений УК — заявитель либо поддержка.
Отсутствующие и недоступные файлы возвращают 404.

## Первая карточка с фотографией

Мини-приложение может создать черновик `issue_card`, загрузить файл по его
`draft_id`, создать карточку через `/issues/create_card`, получить
`reports[0].id` через `/issues/get_card` и вызвать `/files/attach`. Также можно
сначала создать карточку, затем сразу загрузить файл к её первому `report`.
Отправка карточки и прикрепление файла сейчас **не атомарны**: при сетевом
сбое между шагами файл останется staged либо карточка останется без вложения.
Для устранения этого ограничения потребуется передавать `file_ids` при
создании карточки и подтверждать всё одной транзакцией. Повтор загрузки также
не дедуплицируется автоматически.

Если житель выбирает похожую открытую карточку, `/issues/support_card` с
непустым `description` возвращает `report_id`. По нему можно прикрепить
staged-файлы к новому исходному описанию (`issue_report`) и затем отметить
черновик отправленным. В мини-приложении этот путь подключён, но HTTP-шаги
поддержки и прикрепления также не атомарны.

## Вложения через текстового MAX-бота

Отправьте **одно** фото, видео или PDF с подписью-командой:

- `/file draft <UUID черновика>` — сохранить в своём черновике `issue_card`;
- `/file card <UUID карточки> | пояснение` — создать запись в обсуждении видимой
  карточки и прикрепить к ней файл. Пояснение необязательно.

`/filehelp` показывает эти команды в боте. Если отправить файл без команды,
бот не сможет определить его назначение и не сохранит его. `/draft send`
создаёт карточку и привязывает все staged-файлы черновика к исходному
описанию в **одной транзакции БД**. Право на чтение и добавление файла
проверяется тем же доменным сервисом, что и для HTTP API. В закрытую карточку
файл добавить нельзя.

Бот скачивает только HTTPS-адреса известных медиа-серверов MAX, в том числе
после ограниченного числа переадресаций; произвольные внешние ссылки, HTTP,
локальные адреса и вложения сверх 8 МиБ отвергаются. Загрузка идёт потоком,
проверяются сигнатура файла и допустимый тип. Реальную доставку медиа из MAX
нужно проверить на тестовом боте после развёртывания: локальные тесты работают
с имитацией ответа MAX. См. [официальный метод получения видео](https://dev.max.ru/docs-api/methods/GET/videos/-videoToken-)
и [формат входящего сообщения](https://dev.max.ru/docs-api/objects/Message).

Физические файлы записываются под случайными именами с режимом `0600` во
временный файл и публикуются только после полной проверки и `fsync`. При
ошибке записи временный файл убирается. Если БД отказала после записи байт,
может остаться недоступный через API файл; автоматическая очистка таких
остатков пока не реализована. Для сервера дополнительно следует поставить
`client_max_body_size 8m` (или немного больше для HTTP-накладных расходов,
если понадобится изменить контракт загрузки).
