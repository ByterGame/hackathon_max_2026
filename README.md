# СвойДом

«СвойДом» помогает жильцам и управляющей компании вести обращения по дому в
одном месте. Житель получает доступ к своему дому, сообщает о проблеме,
поддерживает уже созданную карточку и видит ход работ. Сотрудник УК проверяет
доступ жильцов, отвечает в обсуждении, меняет статусы и управляет сотрудниками.
Оператор поддержки подключает УК и дома. Основные сценарии проверки находятся
в [SUBMISSION.md](SUBMISSION.md).

## Как устроен сервис

Мини-приложение написано на React, TypeScript и Vite. Оно получает данные
запуска из MAX и обращается к HTTP API на FastAPI. Бот на `maxapi` обрабатывает
текстовые команды и отправляет уведомления. API и бот используют общую
предметную логику: права доступа и изменения карточек применяются одинаково
при работе через интерфейс и через чат.

Данные хранятся в PostgreSQL через SQLAlchemy; миграции схемы выполняет
Alembic. Приватные файлы лежат в отдельном томе и выдаются через API после
проверки прав. Docker Compose собирает интерфейс и запускает PostgreSQL,
миграции, веб-приложение и бота. Для внешнего HTTPS-доступа нужен обратный
прокси, например Nginx; в Compose он не входит. GigaChat может предлагать
название, сводку и похожие проблемы, а при его недоступности работает
локальная подсказка.

## Запуск

Нужны Docker с Compose, действующий токен бота MAX и файл `.env` в корне
репозитория. Если файла ещё нет, создайте его по [.env.example](.env.example)
командой `cp .env.example .env`.
Заполните `BOT_TOKEN`, `PORT`, все `DB_*` и `FILE_STORAGE_ROOT`. Для запуска
через Compose подойдут `PORT=8000`, `DB_HOST=db`, `DB_PORT=5432`,
`DB_NAME=hackathon`, `DB_USER=hackathon` и
`FILE_STORAGE_ROOT=/data/private_files`; задайте собственный `DB_PASSWORD`.
Остальные переменные GigaChat можно оставить как в образце, включая пустые
`GIGACHAT_AUTH_KEY` и `GIGACHAT_CA_BUNDLE`. Существующий `.env` дополните,
не заменяя его образцом; не публикуйте токен и пароль БД.

Выполните из корня репозитория:

```sh
docker compose up --build
```

После успешного запуска при `PORT=8000` доступны
`http://localhost:8000/`, проверка веб-процесса
`http://localhost:8000/service/health` и проверка соединения с БД
`http://localhost:8000/service/ready`. Состояние контейнеров покажет
`docker compose ps`, журналы приложения и бота —
`docker compose logs --tail=200 app bot`. Остановить сервис без удаления
данных можно командой `docker compose down`.

В Compose порт приложения открыт только на `127.0.0.1` хоста. Для работы
мини-приложения из MAX нужен HTTPS-адрес через обратный прокси, например
Nginx; он не входит в Compose. Открывайте мини-приложение из бота MAX:
обычный переход по адресу в браузере не передаёт подписанные данные запуска.
Бот получает сообщения через опрос MAX, поэтому не запускайте второй экземпляр
с тем же токеном. В образце `TEST_MODE=1` включает проверочное
самоподтверждение УК; для обычной работы установите `TEST_MODE=0`.

### Подсказки GigaChat

В образце выбран `ISSUE_AI_PROVIDER=gigachat`, а
`GIGACHAT_SEND_REAL_DATA=0` и `GIGACHAT_AUTH_KEY` пустой. В таком состоянии
заявки продолжают создаваться с локальной подсказкой: описание жителя наружу
не отправляется. Когда получите ключ авторизации GigaChat API и примете
решение об отправке описаний, укажите в `.env` ключ и явно установите
`GIGACHAT_SEND_REAL_DATA=1`. До этого момента ключ для запуска не нужен.

`GIGACHAT_SCOPE` должен соответствовать ключу: `GIGACHAT_API_PERS` для
физического лица, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` для организации.
`GIGACHAT_MODEL` задаёт доступную аккаунту модель; пример использует
`GigaChat-2-Pro`. `GIGACHAT_AUTH_URL` в образце указывает на актуальный
`https://api.giga.chat/api/v2/oauth`. Значения сверьте с
[документацией авторизации GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api)
и [списком моделей](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model).
`ISSUE_AI_PROVIDER=local` отключает внешний вызов независимо от наличия ключа.
Токен доступа GigaChat действует 30 минут по документации провайдера; сервис
кэширует его в памяти процесса и обновляет незадолго до истечения срока.
Перед включением передачи реальных обращений проверьте условия использования
и правила обработки данных. При недоступности GigaChat сервис использует
локальную подсказку и записывает причину переключения в журнал.

При `GIGACHAT_VERIFY_SSL=1` проверка TLS для GigaChat включена: необходим
доверенный корневой сертификат Минцифры по
[инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates).
Если его нет в стандартном хранилище контейнера, получите официальный PEM
по этой инструкции и разместите файл на VPS вне репозитория, например
`/opt/hackathon/certs/gigachat-ca.pem`. Проверьте файл и соединение на VPS:

```sh
openssl x509 -in /opt/hackathon/certs/gigachat-ca.pem -noout -subject -issuer -dates
openssl s_client -connect api.giga.chat:443 -servername api.giga.chat -verify_hostname api.giga.chat -verify_return_error -CAfile /opt/hackathon/certs/gigachat-ca.pem </dev/null
```

Во второй проверке ожидается `Verify return code: 0 (ok)`. Если для цепочки
нужен также выпускающий сертификат, используйте PEM-набор с необходимыми
доверенными сертификатами. Для временной диагностики можно установить
`GIGACHAT_VERIFY_SSL=0`: проверка сертификата отключится только для запросов
к GigaChat (получения токена и вызова модели). В таком режиме сервер нельзя
удостоверить, поэтому ключ и тексты обращений могут быть перехвачены;
верните `1` после диагностики. Ошибку HTTP 403 отключение TLS не исправляет.
Чтобы передать PEM в `app` и `bot` только для чтения, скопируйте на VPS
`compose.gigachat-ca.example.yaml` в `compose.gigachat-ca.yaml`, затем задайте
в `.env`:

```dotenv
GIGACHAT_CA_HOST_PATH=/opt/hackathon/certs/gigachat-ca.pem
GIGACHAT_CA_BUNDLE=/run/gigachat/ca-bundle.pem
```

Запускайте оба Compose-файла вместе:

```sh
docker compose -f compose.yaml -f compose.gigachat-ca.yaml up --build
```

Без дополнительного сертификата оставьте `GIGACHAT_CA_BUNDLE` и
`GIGACHAT_CA_HOST_PATH` пустыми и используйте обычный `docker compose up --build`.
При `GIGACHAT_VERIFY_SSL=0` дополнительный сертификат также не требуется.

## API и документация

Интерактивная документация FastAPI (Swagger UI) доступна
[на развёрнутом сервере](https://168.113.209.86/docs) и после локального
запуска по адресу [localhost:8000/docs](http://localhost:8000/docs) при
`PORT=8000`. Машиночитаемый контракт можно получить по `/openapi.json`;
его полный снимок хранится в [openapi.json](openapi.json). Внутренний
`backend/openapi.yaml` содержит только маршруты, проходящие через
кодогенератор, поэтому для внешней проверки используйте полный контракт.

[DATA-API.yaml](DATA-API.yaml) содержит контрольные запросы к API,
а [submission/test-data.json](submission/test-data.json) — вымышленные данные
для проверки. Запросы от имени пользователя требуют свежих подписанных данных
запуска MAX в заголовке `X-Max-Init-Data`. Правила отдельных маршрутов и
генерации моделей описаны в [документации бэкенда](backend/docs/README.md)
и [документации кодогенератора](backend/docs/codegen.md).

## Установка зависимостей и запуск без Docker

При запуске через Compose зависимости Python и интерфейса устанавливаются
внутри образа. Для локальной разработки нужны Python 3.12, Node.js 24 с npm
и отдельный PostgreSQL. В корневом `.env` укажите адрес этой БД вместо
`DB_HOST=db`: имя `db` доступно только контейнерам Compose. Замените также
контейнерный `FILE_STORAGE_ROOT=/data/private_files` на доступный для записи
абсолютный путь локальной машины вне репозитория. Команды установки из корня
репозитория:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm ci --prefix miniapp
```

Затем примените миграции из корня репозитория:

```sh
(cd backend && alembic -c alembic.ini upgrade head)
```

После миграции запустите три процесса параллельно, каждый в отдельном
терминале из корня репозитория:

- HTTP-сервер: `cd backend && python -m src`;
- бот: `cd backend && python -m src.bot.main`;
- интерфейс: `cd miniapp && npm run dev`.

Для локального интерфейса оставьте `PORT=8000`: на этот порт настроен
прокси Vite. Не запускайте локального бота одновременно с контейнерным при
одном токене.
Для инструментов генерации API отдельно установите
`backend/tools/codegen/requirements.txt`; инструкции находятся в
[backend/docs/codegen.md](backend/docs/codegen.md). В браузере вне MAX
рабочий вход недоступен, так как подписанные данные запуска предоставляет MAX.
